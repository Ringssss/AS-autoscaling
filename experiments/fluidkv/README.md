# FluidKV Native Trace Experiments

The first campaign is stored in `results/native-traces-20260914/`. Its report is
generated by `summarize_pilots.py`; raw results are never rewritten by that script.
The design and outstanding experiments are in
`docs/plans/2026-09-14-fluidkv-trace-evaluation.md`.

## Environment

Run commands from the repository root with the `sdmllm` Python environment.
Core dependencies: numpy, aiohttp, requests, pytest, pyarrow and tokenizers.
The DualMap adapter additionally requires uhashring 2.4 and pympler 1.1 plus
upstream's import dependencies. The first campaign installs those two packages
under `/tmp/fluidkv-dualmap-deps-20260914` rather than changing the environment.

Clone https://github.com/ASISys/DualMap and check out
`24816acc70b8e8f4f6b47bc47b7ce0fdddddf40d`. The adapter checks both this commit
and that the checkout has no local changes. It uses the upstream prefix-key
selector, dual-hash decisions, SLO budget and queue rebalancing. Our harness
replaces HTTP transport and feeds actual generated token IDs into cache metadata.
The upstream cache metadata is not a physical DRAM cache implementation.

## Hybrid pair pilot

Start compatible Qwen3.5 engines with the existing hybrid-state patch. The first
campaign used H100 PCIe GPUs 1 and 3, Qwen3.5-35B-A3B BF16 TP1, 12,288 context,
32,768 full-KV slots, 32 Mamba slots, FP32 recurrent state, Triton linear
attention, CUDA graphs disabled, and skipped tokenizer initialization. Full
server settings are retained in the run directory.

```bash
PYTHONPATH=. python experiments/fluidkv/benchmark_native_pairs.py \
  --manifest experiments/fluidkv/results/new-audit/qwen_pilot_manifest.json \
  --tokens experiments/fluidkv/results/new-audit/qwen_pilot_tokens.npz \
  --output experiments/fluidkv/results/new-pairs \
  --source http://127.0.0.1:31280 --destination http://127.0.0.1:31281 \
  --pairs 32 --repetitions 3 --transfer-port 29880
```

This intentionally fails its overall correctness gate if any cold/cached output
differs, retaining all records and the summary for diagnosis. It separately
records equivalence to sticky cached inference. One-token parent generation
materializes the input boundary; actual generated parent output is not asserted
to match any later recorded input. Prepared state is an isolated readiness
condition, not an observed tool-gap overlap. Source cleanup unpins state; it
does not imply physical GPU retirement.

ToolBench controls are built by `build_toolbench_control.py` using the supplied
validation Parquet file and model tokenizer JSON. Function-call text and recorded
observations are serialized with role labels. No external tool API is invoked
and there are no measured tool durations. The resulting manifest and token NPZ
use the same pair benchmark. `diagnose_cached_continuation.py` tests one pair
on one engine without any migration and retains top-token log probabilities.

## Routing pilot

The first campaign uses three identical H100 PCIe GPUs with Qwen2.5-7B-Instruct
BF16 TP1, 12,288 context, 32,768 KV slots, 32 maximum running requests, CUDA
graphs disabled and skipped tokenizer initialization. Preserve these settings
across policies. Use fresh, dedicated engines; the harness flushes their caches.

```bash
PYTHONPATH=.:/tmp/fluidkv-dualmap-deps-20260914 \
python experiments/fluidkv/benchmark_routing.py \
  --trace /data-aisoft/zhujianian/cloud/FlowPrefill/trace_build/qwen-bailian-usagetraces-anon/qwen_traceA_blksz_16.jsonl \
  --dualmap-source /tmp/fluidkv-dualmap-review-20260914 \
  --output experiments/fluidkv/results/new-routing \
  --engines http://127.0.0.1:31380 http://127.0.0.1:31381 http://127.0.0.1:31382 \
  --requests 128 --time-scale 1 --output-cap 0 --repetitions 3 --causal
```

Zero output cap uses each recorded output length. Causal mode retains original
arrivals but waits for a selected parent to finish if necessary; the resulting
eligibility delay is recorded. Router wait is included in TTFT; dependency delay
is a separate field and must be included when reporting latency from original
arrival. All failures count against SLO attainment. This is a cold-start prefix
of the trace and does not stand in for a warmed, representative full-trace
campaign. Selection limits and missing boundary parents are reported.

## Qwen3.5 logical-retirement campaign

The follow-up campaign lives in `results/qwen35-native-20260914/`. It uses three
H100 engines with Qwen3.5-35B-A3B, 32,768 context, 65,536 KV slots, 64 recurrent
slots, 16 maximum requests, FP32 recurrent state and deterministic FA3/Triton
inference. The deterministic flag does not establish cold/cached equivalence;
the selected 32-pair cold-equivalence gate remains failed.

The runtime in `/data-aisoft/zhujianian/cloud/sglang-hybrid-state` now accepts
`prepare_only` on the async transfer start request. The coordinator prepares
both engines before launching communication. Run the live regression before
capacity-pressure experiments:

```bash
PYTHONPATH=. python experiments/fluidkv/validate_reservation_failure.py \
  --engines http://127.0.0.1:31480 http://127.0.0.1:31481 \
  --output experiments/fluidkv/results/new-reservation-regression
```

The test deliberately reserves all 65,536 destination token slots privately,
checks rejection and rollback, releases the reservation, and immediately retries
on the same group. It requires dedicated engines, not a shared serving endpoint.

```bash
PYTHONPATH=.:/tmp/fluidkv-dualmap-deps-20260914 \
python experiments/fluidkv/run_qwen35_campaign.py \
  --trace-root /data-aisoft/zhujianian/cloud/data/qwen-bailian-usagetraces-anon \
  --dualmap-source /tmp/fluidkv-dualmap-review-20260914 \
  --output experiments/fluidkv/results/new-qwen35-cohort \
  --engines http://127.0.0.1:31480 http://127.0.0.1:31481 http://127.0.0.1:31482 \
  --requests 8 --output-cap 0 --selection exact-parent-cohort \
  --time-scale 4 --retire-at 3 --retire-engine 0
```

Each split selects up to four verified parent/child pairs. These cohorts expose
reuse behavior but are not representative full-trace samples. Setting
`--selection chronological --time-scale 1` retains a chronological prefix and
original timing; check that it includes parent links before drawing reuse
conclusions. `--retire-engine` identifies the physical engine index in the
provided URL list. In-flight callbacks retain their physical identity while
the remaining scheduler slots are compacted. Upstream hashing retains physical
ring anchors across this change.

The planner prototype currently selects full copy or reconstruction with a
simple destination heuristic. Both use the same logical membership event and
ownership store. It is not the full joint scheduler or a physical GPU release
experiment. Actual engine capacity checks remain authoritative; the shared
snapshot-aware router cache is only an estimate. Reconstructed input counts
exclude actual engine cache hits and separately record preparation output.

Generate the campaign report with:

```bash
python experiments/fluidkv/report_qwen35_campaign.py \
  --root experiments/fluidkv/results/qwen35-native-20260914
```
